# Camp listing form: build spec

Nov 15, 2026 · Vineeta Agarwal
Keep at `docs/camps/listing-form/spec.md`.

## What it is

Each camp on the checklist gets an email from Compass with its own private link. The link opens a form on compassbyvavy.ca that already shows what Compass has about that camp. The camp confirms or corrects each fact, fills in what parents ask about, and uploads photos.

Nothing a camp submits goes live on its own. Every answer waits for Vineeta's approval, like Camp Watcher changes. Once she approves, the camp's page shows "Confirmed by the camp, {date}".

Why camps would fill it in: the listing is free, takes no commission, sends parents straight to the camp's own booking page, and a confirmed listing earns parents' trust.

## The camp's link

- Route: `/camps/confirm/[token]`. No login.
- One token per camp, random and at least 32 characters, stored hashed. It works for 60 days and can be reissued.
- Spam protection: Cloudflare Turnstile on submit, and a limit of 5 submits per token per day.
- The page header shows "Compass by Vavy · Listing for {Camp name}", with one line on what Compass is and a link to the camp's current page (or a preview if the page isn't published yet).
- The camp can save and come back, autosaving on the device. A submit can be edited until Vineeta reviews it.

## Each camp gets its own form (decided by code, no AI)

The form is built per camp **by the website at request time**, from data already in Supabase. No AI model is called, and nothing is written by hand for each camp except optional custom questions.

Every field in sections 2 and 3 has a `field_key` that maps to a Camp intake column or a `camp_sessions` column. For each field, the server decides:

| What we have for this field | What the camp sees |
| --- | --- |
| A value, checked since Sep 1, 2026 | **Confirm**: the value, with Correct / Edit |
| A value checked before Sep 1, 2026, or labelled "(2025–26)" | **Confirm**, tagged "Last year's info: still true?" |
| No value | **Fill in**: the empty question |

That means a section 3 question we already have an answer for moves up into "Check what we have", so the camp only types where we have gaps.

**Section 2b, "A few questions about your camp"** (at most 3, shown only when there are some). These are generated by rules, in this order:

1. **Custom questions:** typed by Vineeta on the invite in the admin screen (`camp_invites.custom_questions`). Plain text, at most 3.
2. **Pending Camp Watcher changes:** for each `source_changes` row for this camp with status `pending`: "We noticed {field} changed from {old} to {new}. Which is right?"
3. **Spots:** if every source for this camp has adapter `page` or `manual`: "Where can parents see how many spots are left? Do you keep a waitlist?"
4. **Several locations with different values for the same field:** "{field} is {a} at {location 1} but {b} at {location 2}. Is that right?"

Stop at 3. The camp's answers to these land in `answers` like any other field.

A camp with several locations (e.g. Creative Kids Place) gets one confirm block per location in section 2.

## Form sections

Fields match the Camp intake columns, so approved answers map one-to-one. Which ones show as Confirm or Fill in follows the table above. Every field is optional unless marked.

**1. You**
- Your name\* and role\*
- Email\* and phone, used by Compass only and never shown
- Public phone and email for parents, if different from the above

**2. Check what we have** (pre-filled, one block per program and break)
- Program name
- What kids do (2–3 sentences)
- Category
- Ages or grades
- Venue name and address
- Dates
- Single days available? (yes or no, plus the daily price)
- Hours
- Before care (time and price)
- After care (time and price)
- Price
- Fee notes: sibling discounts, deals and their end dates, membership fees
- When registration opens (date and time)
- Register link

**3. What parents ask**
- What to bring (a packing list)
- Food: is lunch or a snack provided, nut-free or nut-aware, and can you handle allergies?
- Medical and allergy policy (EpiPens, medication)
- Refunds and cancellations
- Staff: ratio, training, first aid, police checks
- Inclusion: support for kids with disabilities or additional needs
- Trips off-site? Where to, and how kids get there (bus or walk)
- Parking and drop-off
- A typical day (short schedule)
- What makes your camp different (max 300 characters)

**4. Your other camps**
- PA days, March Break and summer: dates and register links, if posted. Each one becomes a proposed new session.

**5. Photos and logo**
- Up to 8 photos (JPG, PNG, HEIC, WEBP, max 10 MB each) and 1 logo
- Optional caption and photo credit for each
- Required tick boxes:
  - "I have the right to share these photos, and Compass by Vavy may show them on its listing and on social posts about the listing."
  - "Any children shown are pictured with their parents' permission."

**6. Confirm**
- Required tick box: "To my knowledge these details are correct as of today."
- Typed name\*

## Data

```sql
create table camp_invites (
  id uuid primary key default gen_random_uuid(),
  camp text not null,
  intake_rows int[] not null,          -- Camp intake rows this camp covers
  contact_email text,
  token_hash text unique not null,
  sent_at timestamptz,
  expires_at timestamptz not null,
  opened_at timestamptz,
  submitted_at timestamptz,
  custom_questions jsonb default '[]'::jsonb,  -- up to 3 plain-text questions Vineeta types
  status text not null default 'draft'
    check (status in ('draft','sent','opened','submitted','reviewed','opted_out'))
);

create table camp_submissions (
  id bigserial primary key,
  invite_id uuid references camp_invites(id) on delete cascade,
  submitted_at timestamptz not null default now(),
  contact jsonb not null,              -- name, role, email, phone (private)
  answers jsonb not null,              -- { field: { prefilled, confirmed: bool, value } }
  photos jsonb default '[]'::jsonb,    -- [{ path, caption, credit }]
  photo_rights boolean not null,
  child_permission boolean not null,
  accuracy_confirmed boolean not null,
  typed_name text not null,
  review_status text not null default 'pending'
    check (review_status in ('pending','approved','partly_approved','rejected')),
  reviewed_at timestamptz,
  note text
);
```

- RLS: anyone can insert through the token route, using a server action with a service key. Only admins can read.
- Photos go in a **private** Supabase Storage bucket, `camp-submissions/{invite_id}/`. Approved photos are copied to the public bucket, and only on approval.
- On submit, send one email to `hello@compassbyvavy.ca`: "{Camp} submitted their listing: {n} corrections, {n} new answers, {n} photos".

## Review (admin)

Use `/admin/changes` from the Camp Watcher if it exists by then; otherwise add `/admin/submissions`. For each submission:

- Show what changed against the prefilled value, side by side, and new answers on their own.
- Photos are shown as thumbnails with **use** / **don't use**.
- **Approve all**, **approve some**, or **reject**. Approval writes to `camp_sessions` and to the camp page data, and sets "Confirmed by the camp, {date}".

## Opt-out

The camp's reply goes to Vineeta. Handling follows Decision #34 in the Decisions tab: proposed, waiting for Vineeta's OK. When she marks a camp `opted_out`, it receives no more emails and its photos are never used.

## Invite emails (built by code, sent only when Vineeta presses Send)

Each camp's email is filled in from one template. No AI. The same rules that build the form also work out what goes in the email.

**Template** (Vineeta can edit the wording in one copy file):

> **Subject:** {Camp name} on Compass by Vavy: please check your free listing
>
> Hi {Camp name} team,
>
> I'm Vineeta, a Mississauga mom and the founder of Compass by Vavy (compassbyvavy.ca), a free guide that helps local parents find camps and things to do over winter break, PA days and March Break.
>
> {Camp name} is in the guide. We built your listing from your website, and we already have most of it. {If gaps:} A few things parents ask about are missing: {up to 4 gap labels, e.g. "food and allergies, refunds, staff, photos"}.
>
> Could you take about {minutes} minutes to check it?
>
> [Check my listing] → {their private form link}
>
> The listing is free: no fees, no commission, and parents register directly with you. Listings you confirm show "Confirmed by the camp".
>
> Please share only photos you have the right to use, with permission for any children shown.
>
> Thank you,
> Vineeta Agarwal, Founder, Compass by Vavy
> hello@compassbyvavy.ca · {mailing address}
>
> Prefer not to hear from us? {unsubscribe link}

- `{minutes}`: 2 when we're missing 3 or fewer fields, otherwise 5.
- Gap labels come from the form rules (fields that would show as Fill in), in this order: what kids do, food and allergies, refunds, staff, hours, care, photos.
- `{mailing address}` is one config value. The email doesn't send while it's empty.

**Sending rules:**

- Admin screen `/admin/camps/invites`: a list of camps with an email address, each showing a preview of its email. Vineeta ticks camps and presses **Send**. Nothing is sent automatically.
- At most 20 emails a day, so the domain isn't flagged as spam. The rest wait in a queue.
- Sent from `hello@compassbyvavy.ca` through the email service the repo already uses. Replies go to the same address.
- **One reminder**, 7 days later, only if the camp hasn't opened or submitted the form. Vineeta approves the reminders with one click. There are never more than 2 emails per camp per invite.
- **Unsubscribe:** one click, no login. It sets the invite to `opted_out`, and that camp is never emailed again (Decision #34). Every email names the sender, gives a mailing address and has the unsubscribe link (Canada's anti-spam law, CASL).
- Log every send, open (if the service tracks it) and unsubscribe on `camp_invites`.

## Instructions for Cursor

Build the camp listing form in compassbyvavy-web from this spec:

1. A migration for `camp_invites` and `camp_submissions` with RLS as above, plus a private storage bucket `camp-submissions`. Don't run it against production.
2. The route `/camps/confirm/[token]`: a phone-first form with the six sections, built per camp on the server by the rules in "Each camp gets its own form" (Confirm vs Fill in per field, the last-year tag, and up to 3 questions in section 2b). Pure code: no AI or LLM calls anywhere in this feature. Use Turnstile, the rate limit, autosave and the required tick boxes. Use Compass styling: bg #FAF8F3, pine #33503E, amber #A8763A, ink #26241F, Newsreader headings, Inter body.
3. A server action that validates input, uploads photos to the private bucket, writes `camp_submissions` and sends the notification to `hello@compassbyvavy.ca`.
4. An admin review screen as described, plus a box on each invite where Vineeta can type up to 3 custom questions before sending. Approved photos are copied to the public bucket; nothing goes public without approval.
5. Invite emails as in "Invite emails": the template in a copy file, the `/admin/camps/invites` screen with per-camp preview and a Send button, the 20-a-day queue, one reminder after 7 days, and one-click unsubscribe. Test with a sandbox or test-mode email setting only; send no real emails from the branch.
6. Tests: a field with a value shows as Confirm, an empty one as Fill in, a value checked before Sep 1, 2026 gets the last-year tag; section 2b never shows more than 3 questions and is hidden when there are none; an expired or wrong token gets a friendly error page; a submit without the photo and accuracy tick boxes is refused; a submission never changes public data until it is approved.

Rules: work on a branch, open a PR, send screenshots of the form on a phone, the review screen and two filled-in example emails (one camp with gaps, one without). No commits to main, no deploys, no SQL against production, no real emails sent.
